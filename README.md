# Zepto Data Engineering + AI/ML Project

This repository contains the three required modules in one project:

- `data_pipeline/` — live catalog scraping, cleaning, fixed-rate GBP→INR enrichment, SQLite normalization, SQL and pandas validation.
- `analytics/` — one-load Titanic EDA followed by leakage-safe classification, imbalance comparison, Random Forest tuning, regression, and saved end-to-end model pipeline.
- `support_assistant/` — offline-first RAG service using local sentence-transformer embeddings, ChromaDB, LangGraph, Pydantic structured output, and FastAPI.

## Setup

A single consolidated `requirements.txt` is provided at the repository root. Each module also has its own `requirements.txt` for isolated installation. The root file is the canonical environment specification.

```bash
python -m venv .venv
# Windows: .venv\\Scripts\\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

## Run each module end to end

### 1. Data pipeline

```bash
python data_pipeline/pipeline.py
```

This scrapes the first five All Products pages (at least 60 books), cleans fields, applies the required fixed conversion `1 GBP = 105.50 INR`, recreates `books.db`, executes and saves the required SQL outputs, and validates SQL JOIN versus `pandas.merge`.

### 2. Analytics

Run the EDA first and then modeling:

```bash
python analytics/01_eda.py
python analytics/02_modeling.py
```

`01_eda.py` loads the raw Titanic dataset through `sns.load_dataset('titanic')` once, immediately saves `analytics/titanic.csv`, cleans it, and writes the EDA report/artifacts. `02_modeling.py` reads that same committed CSV and never calls `sns.load_dataset` again.

### 3. Support assistant

The graded path is deterministic and offline from the LLM perspective. Leave `MOCK_LLM` unset (or set it to `1`). The local embedding model is `all-MiniLM-L6-v2` and ChromaDB stores the vectors.

```bash
python support_assistant/build_index.py
uvicorn support_assistant.main:app --host 0.0.0.0 --port 7860
```

Then POST `{"query":"What is the delivery fee below INR 149?"}` and `{"query":"What is the capital of France?"}` to `/ask`.

Docker:

```bash
docker build -t zepto-support-assistant support_assistant
docker run --rm -p 7860:7860 zepto-support-assistant
```

## Design decisions

### Data pipeline

The scraper uses `requests` and `BeautifulSoup` and follows the site's pagination links rather than hardcoding product rows. The first five All Products pages are used, which satisfies the required minimum row count. Price is parsed into `price_gbp`; ratings are mapped from words to integers; availability is converted to `in_stock`. Numeric parsing failures are median-imputed from successfully parsed values, while rows with an unparseable title/category are dropped because those fields are required identifiers/descriptors. The assignment's artificial conversion constant, exactly `1 GBP = 105.50 INR`, is used with no API call. SQLite is normalized into `categories` and `books` with a category primary key referenced by `books.category_id`.

### Analytics

The raw Titanic data is loaded once and persisted as `titanic.csv` immediately. Cleaning follows the assignment's missingness thresholds. EDA and modeling are deliberately connected: modeling starts from the same cleaned CSV. The train/test split occurs before model preprocessing, and all imputers, encoders, and scalers are inside a `ColumnTransformer`/`Pipeline` fit only on training data. SMOTE is applied only to the training fold through an imbalanced-learn pipeline.

### Support assistant

Eight supplied Zepto policy documents are chunked one document per chunk, embedded locally, and persisted in ChromaDB. LangGraph has three named nodes and a conditional intent edge. In the required default mode, intent and answer generation are deterministic; retrieval still runs against the real vector store. `MOCK_LLM=0` is an optional extension for a real provider and does not affect the graded offline baseline.

## Repository acceptance notes

Generated reports and artifacts are textual/structured where possible. Supporting PNG charts are generated by the analytics code, but all interpretations are also written into Markdown reports. The database and model artifacts are regenerable from source scripts. The repository history includes a feature branch with multiple commits merged back into `main`.

## Validation note
The analytics module was executed successfully in the build environment. The live Books to Scrape and local Seaborn dataset endpoints were not network-resolvable in this execution environment, so the data-pipeline scraper is intentionally left as a live `requests`/`BeautifulSoup` implementation rather than replacing the required source with fabricated data. On a network-enabled grading machine, `python data_pipeline/pipeline.py` regenerates the database and SQL output from the real source.
